# Phase 28 advanced TQKV: Q3/Q2/rotation/outlier/pre-RoPE candidate matrix

Spec Phase 28 deliverable (spec §300, §160; exit gate row 28: "≤1% quality
at 128K; memory improves materially"). Spec §160 is explicit: **"No
encoding reaches production solely from perplexity; it must pass long-context
coding/retrieval/tool suites"** and §300: **"No mixed-precision controller
until individual encodings are qualified."** Accordingly this phase builds
and measures five standalone RESEARCH CANDIDATES — none is wired into
`TqkvPagedCache`/`SealedPage`, and none is claimed production-ready.

## What was built

`context::tqkv::candidates`, five independent encode/decode pairs operating
on one page's `[token][kv_head][dim]` array (the same shape
`SealedPage::seal` consumes, so promoting a candidate later is a drop-in
swap):

1. **Q3 symmetric** (§160.1): 3-bit signed, range [-3,3], same
   per-(kv_head,dim)-page-scale convention as Q8/Q4. Generalized the
   Phase 27 nibble packer into an arbitrary-bit-width bitstream packer
   (`pack_bits`/`unpack_bits`) shared with Q4-family candidates.
2. **Q2 asymmetric** (§160.2): 2-bit unsigned codes + per-(token, kv_head,
   64-dim group) min/scale — spec-scoped to cold pages only.
3. **Rotated-Q4** (§160.3): a fixed, deterministic Randomized Hadamard
   Transform (sign-flip + in-place Fast Walsh-Hadamard butterfly,
   normalized to be self-inverse) applied to each 256-dim Key vector before
   Q4 quantization. The sign pattern is a global constant regenerated by
   both encoder and decoder — zero extra storage versus plain Q4.
4. **Outlier-split Q4** (§160.4): bulk Q4 scale from the per-column
   **99th-percentile** |value| (not the true max) plus a sparse
   `(token, head, dim, exact f32)` sidecar for values the tighter scale
   would clip.
5. **Pre-RoPE Q4** (§160.5, §60): quantizes Keys *before* rotary rotation
   and stores each token's absolute position; `decode_one` dequantizes then
   calls the existing `apply_partial_rope` (the same function
   `FullAttentionLayer` uses) to fuse the RoPE fragment at read time,
   exactly as spec §161 describes for pre-RoPE encodings.

Each candidate has its own round-trip/correctness test. A
`candidate_matrix_reports_bytes_and_error_side_by_side` test runs all of
them (plus the Phase 27 Q4 baseline) over comparable synthetic pages and
prints bytes/error side by side — the literal "candidate matrix" the spec
asks for.

## Measured evidence (synthetic, one 256-token page, `--nocapture`)

Uniform-activation fixture (no outliers):

| Candidate | Key payload bytes | vs. BF16 ratio | Max abs error |
|---|---|---|---|
| Q4 (Phase 27 baseline) | 66,560 | 0.254 | 0.2148 |
| Q3 symmetric | 50,176 | 0.191 | 0.5001 |

Frequent-skew fixture (every 8th token has one huge outlier dimension —
the regime rotation targets, *not* rare enough for percentile clipping):

| Candidate | Key payload bytes | Max abs error |
|---|---|---|
| Q4 (no rotation) | 66,560 | 2.8525 |
| **Rotated-Q4 (RHT)** | 66,560 | **1.2195 (2.3x lower, same bytes)** |

Rare-outlier fixture (a single outlier token in the page — the regime
outlier-split targets):

| Candidate | Key payload bytes | Max abs error |
|---|---|---|
| Q4 (no outlier split) | 66,560 | 2.8525 |
| **Outlier-split Q4** | 66,572 (+12 bytes) | **0.2143 (13.3x lower, +0.02% bytes)** |

Pre-RoPE Q4 (`pre_rope_q4_reapplies_rope_and_matches_direct_post_rope_quantization`):
fused dequant-then-rotate reproduces the direct "quantize after rotating"
reference to <0.5 max abs error over 64 synthetic tokens — the fused path
is correct, but this run does not show the pre-RoPE *ordering* itself
reducing error (both paths quantize the same post-rotation dynamic range
in this synthetic fixture, since RoPE is a pure rotation and does not
change per-dimension magnitude for uncorrelated synthetic data — a real
distributional benefit, if any, would need real Qwen Key activations to
surface, not this synthetic check).

Q2 asymmetric: round-trips a uniform synthetic Value page to <1.5 max abs
error (looser than Q3/Q4, as expected from a 2-bit code space; per spec
§61/§160.2 this is explicitly scoped to already-cold, already-compressed
pages with richer SSD backing available, not a general-purpose candidate).

## Interpretation

- **Rotation has a real, measured benefit exactly where the spec predicts
  it** — frequent per-column skew that would otherwise blow up one shared
  scale for every value in that column — at zero storage cost.
- **Outlier-split has a real, measured benefit exactly where *it* predicts
  it** — rare (<1%) large values — at near-zero storage cost (12 bytes for
  one flagged outlier in a 66,560-byte page). Its percentile-based scale
  computation is *not* effective against frequent skew (confirmed by
  running the same technique against the frequent-skew fixture during
  development — the percentile itself gets pulled up by the skew), which
  is why the two techniques are evaluated on different fixtures rather
  than one "universal" outlier fixture: they solve different distribution
  shapes, matching spec §160's framing of these as distinct techniques
  rather than one general fix.
- Q3 trades ~25% smaller key payload for ~2.3x the Q4 baseline's error on
  uniform data — a real, quantified trade, not yet weighed against a
  quality suite.

## Status and remaining work

- **None of these candidates are wired into the live `TqkvPagedCache` or
  `FullAttentionLayer`** — matching spec §300's explicit instruction not to
  build a mixed-precision controller before individual encodings are
  qualified. `TqkvPrecision` (Phase 27) still only offers Q8/Q4.
- All measurements here are synthetic-fixture round-trip error, not the
  spec-required "long-context coding/retrieval/tool suites" pass/fail —
  that combined ≤1% quality qualification does not exist yet in this repo
  for *any* phase (tracked as open in `AGENTS.md`/`CLAUDE.md`), so Phase
  28's exit gate ("≤1% quality at 128K") is not and cannot yet be claimed
  closed. This phase's contribution is qualifying each candidate's
  mechanics and isolated error behavior so a future controller (or a
  future quality-suite run) has real per-candidate numbers to select from,
  per §300's ordering.
- "Memory improves materially" is demonstrated for Q3/Q2 (smaller payload
  at higher error) and is a wash for rotation/outlier-split (same payload,
  lower error) — i.e. these two axes trade against each other differently
  per candidate, which is exactly the Pareto information a later
  controller needs.
- Real Qwen Key/Value activations (vs. this phase's synthetic fixtures)
  have not been run through any Phase 28 candidate; the pre-RoPE ordering
  question in particular needs real activations to say anything beyond
  "the fused decode path is correct."
